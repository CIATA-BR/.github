# Como contribuir com o CIATA

Obrigado por considerar uma contribuição aos projetos do CIATA.

Nosso objetivo é construir tecnologia acessível, sustentável e compreensível. Contribuições de código, documentação, testes, tradução, pesquisa, design e relato de problemas são bem-vindas.

## Antes de começar

1. Leia o README e as orientações específicas do repositório.
2. Verifique se já existe uma issue ou pull request sobre o assunto.
3. Para mudanças maiores, abra uma proposta antes de implementar.
4. Preserve a arquitetura, os padrões e as decisões documentadas pelo projeto.

## Princípios de contribuição

- **Acessibilidade desde a concepção:** não trate acessibilidade como correção posterior.
- **Mudanças pequenas e verificáveis:** prefira entregas focadas, com objetivo claro.
- **Clareza acima de complexidade:** soluções simples, legíveis e documentadas têm prioridade.
- **Conhecimento compartilhado:** registre decisões e aprendizados que possam beneficiar outras pessoas.
- **Respeito às pessoas:** siga o Código de Conduta em todas as interações.

## Relatando problemas

Ao abrir uma issue, informe sempre que possível:

- o que aconteceu;
- o que você esperava que acontecesse;
- passos para reproduzir;
- ambiente, sistema operacional e versão;
- tecnologia assistiva utilizada, quando relevante;
- mensagens de erro, logs ou capturas de tela sem dados sensíveis;
- impacto do problema.

Para problemas de acessibilidade, descreva também:

- leitor de tela ou tecnologia assistiva;
- navegador, aplicativo ou plataforma;
- método de navegação utilizado, como teclado, gestos ou Braille;
- resultado anunciado e resultado esperado;
- frequência e gravidade da barreira.

## Pull requests

Toda pull request deve:

- ter título e descrição objetivos;
- explicar o problema e a solução;
- limitar-se ao escopo proposto;
- incluir testes adequados ou justificar sua ausência;
- atualizar a documentação quando necessário;
- considerar leitores de tela, teclado, foco, contraste, Braille e linguagem clara;
- evitar alterações destrutivas ou incompatíveis sem discussão prévia.

Use a lista de verificação do template de pull request e marque apenas o que realmente foi validado.

## Documentação

Escreva em português brasileiro claro, salvo quando o projeto definir outro idioma de origem.

Prefira:

- títulos hierárquicos;
- frases diretas;
- links com textos descritivos;
- exemplos completos;
- instruções que não dependam apenas de cor, posição ou símbolos visuais;
- nomes completos para teclas e atalhos, como `Control + Enter`.

## Segurança e privacidade

Não publique vulnerabilidades, credenciais, tokens, chaves, dados pessoais ou informações sigilosas em issues e pull requests públicas. Consulte o arquivo `SECURITY.md` para relatar problemas de segurança.

## Licenças e autoria

Ao contribuir, você declara que possui direito de enviar o conteúdo e aceita que ele seja distribuído sob a licença adotada pelo repositório correspondente.

## Dúvidas

Consulte `SUPPORT.md` para saber onde buscar ajuda técnica, institucional ou de uso.

> **Nenhum projeto começa do zero. Todo projeto deixa um legado.**
